# Модель угроз Project Crosshair

Wave005, база `a509d2ebed92f200627bb3a97522a2622db0420a`, 16.10.2026. Модель подготовлена по исходникам и сверена с независимым fresh-context архитектурным обзором. Это **не vulnerability scan**: сценарии ниже — условия/гипотезы для проектирования и проверок, не обнаруженные уязвимости. [SECURITY_MODEL](SECURITY_MODEL.md) определяет механизмы и криптографические ограничения. Отдельный User/MMU/SVC prototype реально прошёл24 cases/48 boot/reset executions на synthetic E2B, с healthy User recovery после каждого case; это функциональное evidence, не аппаратное подтверждение PDA2k или полная sandbox guarantee.

## 1. Обзор

**Summary.** Crosshair — собственная Rust `no_std` ОС в разработке. Фактически принятые исполнения — отдельные privileged diagnostic guests на VersatilePB/reference PXA/synthetic E2A/E2B/display machines, без Linux/CE runtime. Host строит ARM ELF, QEMU loader запускает его, host harness через temporary Unix QMP/QTest sockets управляет CPU/RAM/reset и читает evidence. UI библиотека получает borrowed pixel slice от privileged guest; host tools также статически анализируют фиксированные firmware inputs. Filesystem, phone/network services, key storage и настоящий loader policy не реализованы. Wave005 добавляет отдельный User/MMU/SVC prototype, а не существующую систему приложений.

## 2. Угрозы, границы доверия и допущения

**Assets.** Целостность kernel code, vectors/page tables/exception frames/stacks и MMIO authority; доступность диагностики/recovery и bounded memory; конфиденциальность будущих app/user/key data; корректность modem/storage actions; исходная WM и её RAM state при отдельно разрешённом hardware work; host source/toolchain/evidence integrity, third-party licenses и privacy публичных материалов. Действующих cryptographic secrets, app accounts, network sessions или guest files сейчас нет.

**TrustBoundaries.** (1) native host/build tools → QEMU/loader, (2) host debug plane → вся guest RAM/CPU, (3) User → privileged kernel через MMU/SVC, (4) kernel → privileged drivers/MMIO, (5) unsafe privileged caller → safe UI borrowed buffers, (6) future apps → filesystem/modem/network brokers, (7) future loader/update/storage → executable/data integrity, (8) local research/evidence → public tree. Границы1/2 предполагают доверенный host; 4/5 пока **не privilege separation**. Linux/HaRET/reference source code используется как evidence, не выполняется внутри Rust kernel.

**AttackerCapabilities.** В User prototype условно вредоносное приложение управляет своим code/data/stack, registers и SVC arguments; kernel-controlled mapping/CPSR/page tables/privileged memory оно не должно менять. Исследовательский harness намеренно загружает проверяемые тестовые payloads; сторонний application loader пока отсутствует. Для будущих SD/filesystem/network/modem сценариев attacker контролирует только содержимое/пакеты/ответы на конкретном реализованном transport, не получает заранее kernel/host credentials. Эти transports пока отсутствуют, значит удалённая достижимость не заявляется.

Host owner, actor с QMP/QTest endpoint access или developer, меняющий compiler/QEMU override/привилегированный guest, уже контролирует соответствующий TCB. Его способность менять guest memory не является User escape, а выполнение выбранного им host binary — не новый privilege gain. Физический attacker/скомпрометированная WM может контролировать pre-boot/RAM/storage; без root of trust против этого нельзя обещать verified boot или защиту работающих secrets.

**SecurityObjectives.** Default deny User access к kernel/vectors/tables/stacks/MMIO; bounded authorized copy-in/out и корректный exception return; unknown syscall/error не выполняет privileged operation; один User fault не повреждает kernel и допускает healthy replacement. Для будущих brokers — owner/rights/generation checks и explicit capabilities; для cryptography — entropy availability, authenticated metadata/unique nonces, key lifecycle и fail closed; для evidence — честный статус, privacy/license separation и воспроизводимые хеши. Не выдавать SVC proof за filesystem permissions, hardware readiness или production app sandbox.

**Assumptions.** Trusted host OS/compiler/build scripts/QEMU/loader и privileged guest/BSP; single CPU, synthetic RAM и заданный reset contract. QEMU CPU260/functional page walk/cache NOP не доказывают PXA263 silicon behavior. ARMv5 AP не предоставляет современный XN: User RW memory остаётся executable ([ARM DDI0100I B4-8..9](https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/1023/ARM-Architecture.pdf#page=708)). ELF flags/hash manifests — metadata, не root of trust. Нет scheduler/preemption/availability guarantee, DMA/IOMMU proof, real filesystem/modem/network, CSPRNG/SecretStorage/signature-loader/AEAD runtime. Physical loading и изменение Flash/Radio/SD не разрешены этой моделью. Initial export audit не распространяется автоматически на новые изменения.

Прямой контроль host QMP и привилегированного test guest — accepted developer authority, поэтому не называется elevation. Hardware attack, unsafe physical loader/power procedure и реальные RF/SIM actions остаются отдельными owner-authorized workflows; эта таблица их не запускает. Отдельные questions: точный PXA263/cache/DMA behavior; app identity/permissions/process lifetime; timing-safe crypto на этом CPU; entropy/seed/reseed source; persistent key/nonce/rollback/recovery policy; доверенный update key и hardware root; физический modem/input/storage contracts.

## 4. Калибровка серьёзности

Это правила оценки будущих подтверждённых дефектов, не присвоенные severity существующему коду. **Critical** потребует доказанного широкого/устойчивого privileged compromise на реально доступной поверхности, например remote parser→kernel→persistent trusted update, с установленной достижимостью; наличия слова modem/unsafe недостаточно. **High** — доказанный User→kernel escape, privileged arbitrary memory/MMIO или раскрытие будущих секретов через обычный разрешённый интерфейс; отрицательные тесты должны показать конкретный обход, а не полагаться на предположение.

**Medium** — ограниченный cross-boundary DoS/data corruption или нарушение app ownership с доказанными victim/prerequisites и ограниченным impact. Nontrapping User loop сейчас — известный предел отсутствующей preemption, не внезапно найденная scheduler vulnerability. **Low** — ограниченная утечка нечувствительных metadata/локальный policy defect с небольшой новой возможностью; опечатка отчёта без security impact не становится finding.

Уже имеющий full host/privileged TCB control actor не «эскалирует» тем, что использует QMP или меняет выбранный executable. Отсутствующий modem/filesystem/secure loader не создаёт сегодняшнюю remote exposure. Future encryption без entropy — блокирующая предпосылка, а не работающий security feature. Impact, confidence, reachability и остающийся proof gap фиксируются отдельно; hardware success не выводится из TCG.
