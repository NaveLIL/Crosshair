# E2A: экспериментальный профиль CPU для Blue Angel

Дата: 16.10.2026. Узкая проверка ISA/MIDR, GPIO, timer/IRQ и RAM. Boot 0.1 и E1 уже завершены; здесь их тесты не повторялись. Физическое устройство не использовалось.

**Инженерный вывод:** для `crosshair-blueangel-e2a` допустим QEMU `pxa260` как явно обозначенный **экспериментальный PXA26x ISA proxy**, с его настоящим модельным MIDR `0x69052903`. Это не реализация PXA263. Не следует переименовывать Connex, подменять MIDR на предполагаемый «263» или переносить полный PXA270 SoC. Минимальные собственные timer/PIC и RAM contract реализованы отдельно от CPU и [явно описаны](E2A_CONTRACT.md). E2A прошёл собственный guest и QTest; [фактический отчёт](../reports/E2A_MINIMAL_BOARD.md). Это завершение ограниченного эксперимента, а не всего E2 с GPIO.

Статусы: **ИСТОЧНИК** — подтверждено закреплённым кодом или документацией; **МОДЕЛЬ** — характеристика QEMU, не измерение кремния; **РЕШЕНИЕ E2A** — ограничение нашего эксперимента; **ПРОВЕРЕНО** — фактический emulator test; **ВЫВОД** — явно указанное следствие источников; **НЕИЗВЕСТНО** — пока не установлено для экземпляра PDA2k.

## Разрешённый смысл экспериментальной модели

**РЕШЕНИЕ E2A:** defaultCPU `pxa260`, собственная board composition, ограниченные RAM/vector-loader/diagnostic/timer/PIC contracts, unsupported MMIO явно виден. Guest может проверять ARM exception entry/return, IRQ routing/ack, timer arithmetic и RAM reservations. `pxa255` допустим как явно выбранный сравнительный ISA proxy; результат такого запуска должен хранить другой model MIDR и не называться PXA263 validation. PXA270 остаётся E1 comparator; его дополнительные возможности не входят в контракт целевого263.

ResetSCTLR `0x78` и CTR `0x0d172172` у Q91 CPU260 — **МОДЕЛЬ** (`cpu32.c:833–838`), не полученный с аппарата register dump. Новый source audit должен отдельно проверить MMU/cache/control semantics, reset type и XScale-specific CP14/15 перед запуском более сложного кода; часть clock/power регистров создаётся SoC, а не одним выбором CPU. Отсутствие ошибки на TCG не доказывает cache coherency, DMA ordering, silicon errata или400MHz timing.

**НЕИЗВЕСТНО для физического экземпляра:** точный MIDR/stepping и errata; текущие CP14/15 и cache/MMU state после выбранного HaRET; физические банки и aliases RAM; действительные clock/power/wake/reset sequences; GPIO board state; IRQ polarity downstream ASIC; Flash timing/boot straps. E2A не закрывает эти пункты и не разрешает аппаратный запуск.

**РЕАЛИЗОВАНО И ПРОВЕРЕНО:** machine `crosshair-blueangel-e2a` на отдельной QEMU9.2 использует CPU260+собственные timer/PIC/RAM contracts. TCG guest выполнил UART, три реальных CPU IRQ с exception return, повторный запуск после system reset и четыре независимых data-abort probes. QTest подтвердил ровно3 686 400 ticks за виртуальную секунду, IRQ/FIQ routing/masking, W1C isolation, rollover, reset и отсутствие старых callbacks после повторного enable. Прочитаны фактические `target/artifacts/e2a-tests/*/result.json`, UART и `target/artifacts/e2a-qtest/result.json`; хеши гостевых файлов и QEMU сверены с самими файлами. Полный [контракт](E2A_CONTRACT.md) и [отчёт с evidence](../reports/E2A_MINIMAL_BOARD.md) задают границы результата.

**ИСТОЧНИК / ВЫВОД:** Intel DM §4.4.2.1–2 и [таблица4-45, печатная4-40](https://intel.manymanuals.com/laptops/pxa26x/user-manual-435/148) задают OIER как разрешение match→OSSR; отключение enable не очищает уже установленный OSSR. Из описанного пути status→PIC следует сохранение IRQ до W1C; это вывод по документации, согласующийся с Q91, а не измерение PDA2k. В E2A оба поведения проверены QTest.

Следующий конкретный шаг **E2B** — source audit CP14/CP15/reset и спецификация PXA26x GPIO с особенностями86–89, затем отдельная минимальная реализация и тесты. Для заявления точности PXA263 нужны закреплённые manual/errata и позднее разрешённые аппаратные traces. Экранный renderer остаётся отдельной будущей задачей и не закрывает отсутствие ATI LCD-модели.
