# Crosshair Security Foundation 0.1

Wave005, 16.10.2026; принятая база `a509d2ebed92f200627bb3a97522a2622db0420a`. Статусы: **проверено** — код/исполнение с evidence; **источник** — документация или закреплённый код; **проект** — требование без реализации; **неизвестно** — неподтверждённое свойство. Это инженерная модель безопасности, не сертификат защищённости и не результат полного security scan. [Модель угроз](THREAT_MODEL.md) содержит допущения и условные сценарии.

## Реальная граница текущего ядра

Прежние Boot/E1/E2A/E2B/display guests — отдельные `no_std` диагностические образы с привилегированным ядром. [E2B entry17–29](../src/arch/e2b_entry.S#L17) устанавливает SVC/стек; [E2B MMU test173–205](../src/e2b.rs#L173) временно использует AP3, проверяет alias и выключает MMU. Это **не изоляция приложений**. [UI Surface132–164](../ui/src/lib.rs#L132) проверяет размеры/stride/borrowed slice и запрещает `unsafe` в UI crate; [display caller179–198](../src/display_test.rs#L179) остаётся privileged. Safe Rust API не создаёт отдельного уровня привилегий.

Wave005 реализовал и **проверил в TCG отдельный User Mode/MMU/SVC prototype на неизменённой E2B machine**:24 cases,48 boot/reset executions, с новым healthy User контекстом после каждого primary case. [Исходник](../src/security.rs), [entry/traps](../src/arch/security_entry.S), [linker](../link/security.ld), [независимые host assertions](../tools/smoke_security.py#L199), [команда проверки](../scripts/test-security.sh). Actual JSON создаётся в `target/artifacts/security-tests/result.json` и `case-00..23/result.json`. Прежние privileged guests не переоборудованы в sandbox; scheduler, multitasking, filesystem, modem/network stack или аппаратный BSP не добавлены.

**Проверено:** User denied kernel/MMIO read/write, RO-code write и guard access, privileged CP15; valid/max/zero-length copy, invalid pointers/boundary/overflow/length/number/immediate; реальные data/prefetch abort и UNDEF, завершение неподдержанного User SVC origin и recovery. Case16 действительно исполняет два ARM слова из User RW data и возвращается к RO code — это положительный контроль отсутствия XN, не обход заявленной NX защиты. Cases20–23 отдельно проверяют ARM SVC/UNDEF из data, unmapped instruction fetch и Thumb SVC; kernel не читает opcode непроверенного PC и завершает только этот контекст. Host проверяет фактические descriptors/CPU modes/opcodes/frames/canaries, а не только PASS banner.

Memory accounting этого теста: kernel reservation78848B (включая33792B BSS,28KiB privileged stacks и alignment), плюс три4KiB User pages=**91136B**, плюс64B vectors=**91200B**. User code480B занимает собственную4KiB RO page; guard VA не имеет backing allocation. Flat BIN2064864B содержит нулевой адресный gap до PA`a0200000`, поэтому его длина **не расход working RAM**. Debug ELF1120060B также не является RAM footprint. Источники — [linker](../link/security.ld), generated `target/artifacts/security/image/{image.json,size.txt}` и actual runtime records; scheduler/context manager, heap и crypto state отсутствуют.

Целевой TCB минимального монолитного ядра включает entry/vectors, exception return, linker layout, page tables/MMU setup, syscall validation, kernel memory и все привилегированные BSP/драйверы. Ошибка драйвера в kernel mode может нарушить всю систему. Перенос драйвера в отдельный protection domain — последующее решение, не существующая изоляция.

## ARMv5/PXA: допустимые обещания

**Источник:** ARM *Architecture Reference Manual*, **DDI0100I**, B4-8..B4-10 и B4-24 ([оригинальный документ ARM на сервере TI](https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/1023/ARM-Architecture.pdf#page=708)). AP при Client domain: `01` — privileged RW/User none; `10` — privileged RW/User RO; `11` — RW обоим. AP00 зависит от SCTLR S/R, поэтому не заменяет отсутствие descriptor. Domain Manager обходит AP: untrusted memory нельзя защищать одним AP при DACR Manager. Для используемого legacy формата L1 table выровнена на16KiB.

APX/XN появились в VMSAv6. ARMv5TE/PXA263 не получает современную NX/W^X гарантию из ELF `R/W/X` flags: доступная User RW page может содержать исполняемые инструкции. Отдельные RO code/RW data mappings полезны против записи кода, но не запрещают исполнение data/stack. Отсутствие User mapping запрещает и data access, и instruction fetch в этом адресном пространстве; это другой механизм. Нельзя обещать ASLR, PAC, TrustZone, secure enclave или аппаратный keystore без отдельного доказательства.

Для текущего CPU260 proxy установлены functional CP15/MMU и отсутствие cache implementation; [аудит E2B](E2B_CPU_GPIO_AUDIT.md) фиксирует source/version и cache maintenance NOP. Это не доказательство PXA263 cache/TLB timing, DMA isolation, errata или side-channel resistance. Привилегированный host/QMP может менять guest RAM независимо от guest MMU; host входит в trusted development environment.

**Реализовано и проверено функционально:** [MMU setup171–214](../src/security.rs#L171) оставляет прочие descriptors нулевыми, kernel/vectors/page tables/privileged stacks/MMIO identity-maps с AP1, domain0 Client (`DACR=1`), `PID=0`, SCTLR=`0x79` (MMU on, caches off). User получает coarse L2 small-page mappings; ELF загружается по PA до включения MMU. [Linker26–30](../link/security.ld#L26) проверяет table/stack alignment и размер code page.

| User VA, half-open | Backing PA | AP / назначение |
|---|---|---|
| `[01000000,01001000)` | `a0200000` | AP2 во всех четырёх1KiB subpages: User RO ARM fixture code |
| `[01001000,01002000)` | `a0201000` | AP3: User RW data, единственный допустимый syscall copy-in range |
| `[01002000,01003000)` | Нет mapping | Guard; translation fault |
| `[01003000,01004000)` | `a0203000` | AP3: User RW stack, initial SP=`01004000` |

[User entry34–58](../src/arch/security_entry.S#L34) задаёт kernel-controlled PC/SP и SPSR=`0xd0` (User ARM, IRQ/FIQ masked). [Trap entry61–93](../src/arch/security_entry.S#L61) сохраняет64B frame на banked privileged stack; syscall return использует сохранённые registers/LR/SPSR, termination возвращается к kernel-owned SVC call frame. Пользователь не выбирает privileged mode, TTBR/DACR, exception target или kernel SP. Это один последовательный контекст; capability manager/context switching не реализованы.

ABI разрешает ARM `svc #0` только из установленного RO fixture code, номер в r7. `0=Exit` завершает только текущий тестовый контекст; `1=Copy` переносит до64 bytes из declared data page в собственный kernel buffer, **не выполняет modem/file/MMIO operation**. Return r0 — length либо `-EFAULT=-14`, `-EINVAL=-22`, `-ENOSYS=-38` для разрешённого origin. SVC из RW data/Thumb завершает контекст как unsupported origin. [Pure policy9–19](../src/security_policy.rs#L9) сначала проверяет cap, затем checked-add и весь диапазон; zero length разрешён только с ptr в closed `[01001000,01002000]`, null отвергается. [Handler363–412](../src/security.rs#L363) проверяет номер/immediate и policy **до первого user-byte read**; [opcode reader226–245](../src/security.rs#L226) проверяет страницу/alignment перед чтением. Это узкая data-page allowlist, не общий page-table-aware `copy_from_user` для будущего loader; general user pointers потребуют отдельного дизайна. [FNV-style hash86–89](../src/security.rs#L86) — диагностический checksum для тестов, не криптографическая подпись/MAC или доказательство авторства.

## Границы подсистем

| Граница доверия | Правило и текущий статус |
|---|---|
| Kernel ↔ приложения | **TCG-проверенный prototype Wave005.** Только описанные Exit/Copy SVC с data-page/length/overflow validation; general copy-out, handles и app loader не реализованы. Будущие handles должны быть opaque, привязаны к owner/rights/generation; PID и числовой handle из User сами по себе не авторизация |
| Kernel ↔ privileged drivers | **Текущий TCB.** MMIO только после доказанной карты/width/alignment; documented `unsafe`, timeout/error state. Driver не становится изолированным из-за отдельного Rust module. IRQ/DMA ownership, lifetime и cache visibility требуют отдельных контрактов |
| Applications ↔ filesystem | **Не реализовано.** Отдельные owner/permissions, bounded paths, validated names, mount policy и crash-safe commits; дескриптор файла не равен произвольному block/MMIO доступу. Съёмный носитель и metadata считаются недоверенным вводом; parser failures не исполняют содержимое |
| Applications ↔ modem/network | **Не реализовано.** Privileged broker отделяет конкретные capabilities (call/SMS/network/configuration), validates framing/length/state и не отдаёт raw modem/power/Flash commands приложениям. Внешние пакеты/ответы модема недоверенны; registration/delivery сообщает backend, не UI. Проверенный transport/IRQ/wake ещё отсутствует |
| Loader ↔ kernel image | **Development trust.** QEMU загружает наш ELF из host path; manifest hashes обнаруживают mismatch, но не устанавливают автора. HaRET RAM handoff наследует привилегированное WM окружение; safe RAM/return contract не доказан. Подпись будущего manifest полезна только с доверенно установленным public key и проверкой до исполнения |
| Host tools / QEMU ↔ guest | **Доверенный host.** QMP/QTest/ELF loader имеют полное управление гостем. Unix sockets в temporary directory уменьшают случайное вмешательство, но не являются защитой от host owner; guest MMU не ограничивает QMP. C model bounds не дают обещания host sandbox |
| Evidence/publication ↔ внешние читатели | Проверяются конкретный diff, provenance, лицензии и отсутствие private data; [политика](../RIGHTS_AND_PUBLICATION.md). Initial allowlist export — исторический снимок, дальнейшая работа идёт в public checkout. Pattern scan/hashes не являются универсальной DLP или криптографическим approval gate |

Default privilege будущего приложения — только собственная память и явно выданные handles. Installation, granting phone/network/storage access и владелец данных требуют отдельной policy. В Wave005 нет пользователей, filesystem ACL, устойчивого app identity или capability manager; narrow syscall test не доказывает их наличие. Trapped fault/unsupported origin тестового User контекста завершает его и допускает новый healthy context; IRQ/FIQ остаются masked, поэтому **nontrapping бесконечный User loop не ограничен**. Trusted host harness имеет timeout, но это не guest preemption/watchdog или доступность телефона.

## Дополнение Wave006: отдельный вытесняемый task guest

16.10.2026, база `d7f39d7968bd5163e908abe8911ca05e960eefd2`. Разделы выше сохраняют исторический scope Wave005 и его отдельного `crosshair-security`; его IRQ-masked/recovery поведение не изменено. **Реализовано в новом `crosshair-tasks`:** два kernel-owned Task id,80B full User contexts (r0–r12/User SP/LR/PC/CPSR), Ready/Running/Exited/Faulted, отдельные L1/L2 и timer IRQ round robin на той же E2B. [Контракт и unsafe boundaries](TASK_RUNTIME.md), [код capture/restore](../src/arch/tasks_entry.S#L38), [tables/TTBR/TLBI](../src/task_runtime/memory.rs#L85), [SVC](../src/task_runtime/syscall.rs#L15), [точное evidence исполнения](../reports/WAVE_006.md).

**Код / граница:** обе задачи используют User VA`01000000..01004000`, но только собственные code/data/stack PA: A=`a0200000/a0201000/a0203000`, B=`a0300000/a0301000/a0303000`; guard`01002000` unmapped. Identity RAM/MMIO/vectors/table/stack aliases остаются AP1, domain0 Client, PID0, caches off. При dispatch TTBR меняется вместе с full TLBI/cpwait; общий privileged kernel mapping сохраняется. User I=0/F=1; все kernel/exception/syscall paths I=F=1, nested IRQ нет. Bounded Copy завершается до смены task/mapping, использует проверенную policy и caller-owned PA alias. Thumb — User-controlled state: IRQ capture его сохраняет, unsupported Thumb SVC переводит задачу в Faulted; это не kernel assertion failure. ARMv5 XN/ASID/cache timing/DMA guarantees не добавлены.

**Новая узкая проверка:** [harness](../tools/smoke_tasks.py#L200) читает actual CPU/RAM/tables/ELF и требует Busy Loop без SVC при progress другой задачи, fault isolation, register/flags sentinels, syscall returns и reset boots; точные результаты и hashes находятся в Wave006 report. Nontrapping User loop перестал быть неограниченным в этом отдельном task guest; это не доказательство production availability телефона или real-time latency. Диагностический stop reason1 может оставлять Ready задачи ради snapshot; настоящий no-runnable Idle имеет reason2. Exited/Faulted memory сохраняется до reset, reuse отсутствует. General loader, app authority/handles, filesystem/modem/network и crypto services остаются не реализованы; аппаратная защита PXA263 не заявляется.

## Криптографические границы: пока контракты

Ни CSPRNG, ни SecretStorage, ни signed loader, ни AEAD runtime в Crosshair не реализованы. Не генерировались ключи и не шифровались пользовательские данные. Отдельный compile-only эксперимент ниже проверяет совместимость библиотек с target, не безопасность интеграции.

| Интерфейс будущего сервиса | Обязательный контракт / отказ |
|---|---|
| `CSPRNG.fill(out) -> Result` | Единственный serialized owner состояния; обоснованный initial entropy/reseed input, ограниченные requests/reseed budget, health/failure state. До готовности энтропии — `Unavailable`, без частично выданного «случайного» результата. Timer jitter, QEMU clock, IMEI/serial/MAC, uptime, keyboard cadence и fixed test seed не считаются доказанной секретной энтропией. DRBG не создаёт её из ничего |
| `SecretStorage` | Opaque owner-bound key IDs, назначение/алгоритм/поколение и explicit rights; raw key export запрещён по умолчанию. Create/use/delete имеют проверяемый результат; persistence требует crash-safe commit, nonce/version policy и recovery. Plaintext/key material не попадает в logs/UI/core dumps; buffer lifetime/zeroization и остаточные копии проверяются отдельно. Без trusted storage/entropy сервис недоступен; никакого hardcoded fallback key |
| `VerifySignature` | Bounded canonical manifest/message, fixed algorithm/version/context и exact signature/key lengths; pinned authorized public key, fail closed на malformed/unknown key/invalid signature. Для Ed25519 использовать strict verification, без hazmat/legacy compatibility. Проверка подписи не даёт confidentiality, anti-rollback, revocation или secure boot сама по себе |
| `AEAD.seal/open` | Выбранный reviewed algorithm/library, key-use policy, bounded lengths и authenticated metadata (format/version/owner/object/sequence). Для RFC8439 ChaCha20Poly1305: key32B, nonce12B, tag16B; nonce никогда не повторяется с тем же key, tag не усекается. `open` не выпускает plaintext до проверки; при error caller уничтожает/не использует buffer. Crash/reset/retry/rollback не должны переиспользовать nonce; до durable uniqueness policy persistent encryption недоступно |

Основания AEAD lengths/nonce/tag: [RFC8439 §§2.8,4](https://www.rfc-editor.org/rfc/rfc8439.html#section-2.8). Key provisioning/rotation/revocation, парольная KDF и sealed storage требуют отдельного протокола и выбора готовой реализации; собственные криптоалгоритмы не разрабатываются. Нет подтверждённого аппаратного root of trust/keystore/secure boot для данного экземпляра. Software-only хранение не защищает от privileged kernel compromise или физического извлечения ключей из работающей RAM. Это неизвестные/ограничения, а не утверждение об отсутствии любой аппаратной возможности в PXA family.

## Проверенный compile-only выбор кандидатов

Официальные документы/registry проверены 16.10.2026. [Манифест](../research/crypto-candidates.json) содержит exact versions/checksums/VCS revisions, source hashes, probe source/manifest/lockfile и результат; root Cargo/UI не менялись.

| Кандидат | Закрепление и результат |
|---|---|
| RustCrypto `chacha20poly1305=0.11.0` | MSRV1.85; `default-features=false, features=["zeroize"]`. **ARM compile PASS** detached decrypt/open; без runtime alloc/std/getrandom. Default features включают alloc/getrandom, поэтому defaults непригодны без проверки. [Pinned Cargo/source](https://github.com/RustCrypto/AEADs/blob/e37a978ccf0992d9053fbc039470d6527108e393/chacha20poly1305/Cargo.toml) |

| `getrandom=0.4.3` | MSRV1.85; default-features off **не создаёт entropy backend**. Отдельная ARM сборка ожидаемо завершилась `target is not supported`. Ни custom, ни unsupported-success backend не добавлялся. [Официальный contract](https://docs.rs/getrandom/0.4.3/getrandom/) |
| `rand_chacha::ChaCha20Rng` | Дополнительный DRBG-кандидат по [официальной документации0.10.0](https://docs.rs/rand_chacha/0.10.0/rand_chacha/), **не собран/не интегрирован** в этом эксперименте. Требует настоящего seed; выбирать runtime implementation можно только вместе с entropy/reseed design |

Выбор для следующего эксперимента: готовые strict Ed25519 verification и ChaCha20Poly1305 implementation выше; **не разрешение включить secrets/encryption без entropy/storage/timing review**. [NCC Group audit2020](https://www.nccgroup.com/research/public-report-rustcrypto-aesgcm-and-chacha20pluspoly1305-implementation-review/) относится к тогдашним AES/GCM/ChaCha20+Poly1305 revisions. [Quarkslab2019](https://blog.quarkslab.com/security-audit-of-dalek-libraries.html) в основном проверял subtle/curve arithmetic, ed25519 получил более узкий обзор. Они не удостоверяют весь нынешний dependency graph, ARMv5 compiler output или нашу будущую интеграцию. [RustSec2022-0093](https://rustsec.org/advisories/RUSTSEC-2022-0093.html) для прежних dalek signing APIs исправлен в2+; это один проверенный advisory, не полный dependency security audit.

RustCrypto отдельно требует constant-time multiplication для portable Poly1305 ([security notes](https://docs.rs/chacha20poly1305/0.11.0/chacha20poly1305/#security-notes)). Время умножения/утечки на конкретном PXA263 и compiler output **не измерены**. Compile PASS и QEMU cache NOP этого не проверяют. Верификация public signatures не требует генерации секретного ключа на PDA; signing, key agreement и TLS здесь не реализованы.

Реальный probe: `nightly-2025-03-01`/rustc1.87.0-nightly/LLVM20.1, `armv5te-none-eabi`, `-Zbuild-std=core`, compiler-builtins-mem, release `opt-level=z`. Получен ARMv5TE ELF32LE/EABI5 **relocatable object43892B**, SHA-256=`1df0c0bf29c98fe1cd820092f0b238042059d8fc93d95600616fc3bb82395091`. Это не runnable ELF, размер готового crypto subsystem, performance или RAM/stack bound. Host build scripts/proc macros исполнялись как часть доверенной сборки; функции probe AEAD/Ed25519 и keygen не исполнялись. `semver/std` встречается у **host build dependency**, а не в ARM runtime.

Для повторения в отдельном disposable каталоге восстановить три строки файлов `probe.Cargo.toml`, `probe.src/lib.rs`, `probe.Cargo.lock` из JSON под именами `Cargo.toml`, `src/lib.rs`, `Cargo.lock`, задать отдельные `CARGO_HOME`/`CARGO_TARGET_DIR` и существующий project `RUSTUP_HOME`, затем выполнить `probe.command` через `rustup run nightly-2025-03-01`. Не подключать probe к корневому workspace. Проверить crate checksums и lock hash; feature tree с `-e features,no-build,no-dev` не содержит alloc/std/getrandom. Отрицательный entropy probe отдельно использует только getrandom0.4.3 и вызов `fill`, без custom backend.

У actual pinned target нет `target_has_atomic="..."` CAS/RMW cfg; unstable load/store cfg не даёт lock-free queue/CSPRNG singleton contract. [Официальные ограничения Rust atomics](https://doc.rust-lang.org/stable/core/sync/atomic/#portability). Будущий сервис должен иметь serialized ownership/обоснованный critical-section design; нельзя незаметно полагаться на Linux atomics helpers или стандартный mutex.

Следующий критерий: сохранить эти regression cases и определить bounded app lifecycle/authority, User scheduling/preemption и более общий syscall ABI отдельным контрактом; crypto остаётся недоступным до доказанного entropy и key-lifecycle contract. Физические процедуры, сетевой transport, Flash/Radio/SD и загрузка на PDA не входят в Wave005.
