## Общий критерий качества каждой модели

До интеграции записать MMIO width/alignment/reset values/read/write effects, IRQ ack semantics, доступность clock/power, FIFO/descriptor bounds и поведение ошибки. Неизвестный регистр не должен незаметно читать ноль и делать неполную модель похожей на исправную плату. Тесты охватывают reset, invalid accesses, overflow/truncation, timeout и pending interrupt; QTest подходит для register-level тестов, собственный guest — для исполнения драйвера.

Каждый отчёт сохраняет emulator source commit + build hash + guest hash + machine config + scenario/seed + virtual timeline + ожидаемый/фактический результат. Уровни `functional`, `register-level`, `hardware-validated` присваиваются по подсистеме; текущий статус аппаратного подтверждения всегда **none**, пока нет разрешённых измерений. Для зависимостей фиксируются происхождение и лицензия; чужие ROM/firmware/персональные traces не включаются автоматически.

## Следующая конкретная работа

На основе [исследования W3200](../docs/ATI_W3200_SPEC.md) определить отдельную границу **ATI backend**: metadata активного framebuffer (PA, bounds, width/height, signed x/y stride, format/orientation), chip/panel identity, retained state и completion/cache contract. Сначала проверить metadata fixtures и source-derived register rules без устройства; неоднозначности reset access, PLL и cold-init не подменять synthetic значениями. Модель ATI и аппаратный display driver ещё не реализованы.

Для физического ввода отдельно установить transport/scancode либо touch metadata и calibration; проверенный logical-input FIFO Wave004 не задаёт распиновку, IRQ или скан-коды клавиатуры PDA. Аппаратные процедуры требуют отдельного разрешения.

E1/E2A/E2B сохраняются как проверенные regression baselines. [Аудит E2B](../docs/E2B_CPU_GPIO_AUDIT.md) фиксирует remaining unknowns: точный PXA263/stepping, cache/DMA behavior, полный CP14/15, физические RAM/IRQ/pin contracts и sleep/wake. M1 QwertyKey и E3 ASIC3/QWERTY сохраняют отдельный приоритет.
