## Общий критерий качества каждой модели

До интеграции записать MMIO width/alignment/reset values/read/write effects, IRQ ack semantics, доступность clock/power, FIFO/descriptor bounds и поведение ошибки. Неизвестный регистр не должен незаметно читать ноль и делать неполную модель похожей на исправную плату. Тесты охватывают reset, invalid accesses, overflow/truncation, timeout и pending interrupt; QTest подходит для register-level тестов, собственный guest — для исполнения драйвера.

Каждый отчёт сохраняет emulator source commit + build hash + guest hash + machine config + scenario/seed + virtual timeline + ожидаемый/фактический результат. Уровни `functional`, `register-level`, `hardware-validated` присваиваются по подсистеме; текущий статус аппаратного подтверждения всегда **none**, пока нет разрешённых измерений. Для зависимостей фиксируются происхождение и лицензия; чужие ROM/firmware/персональные traces не включаются автоматически.

## Следующая конкретная работа

Выполнить **E2**: установить документированные различия PXA263/26x против reference PXA255/270, выделить минимальные CPU/GPIO/PIC/timer/reset contracts, затем реализовать отдельно названную ограниченную machine на выбранной новой базе QEMU. Неизвестные свойства остаются явно unsupported. Текущий E1 уже даёт comparator и reset regression; `crosshair-blueangel` ещё не поддерживается.
